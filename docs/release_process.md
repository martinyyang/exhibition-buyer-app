# Release APK 冒烟测试流程

## 概述

本文档定义了 Release APK 的冒烟测试流程，确保每次发布前捕获所有已知的启动和核心功能问题。

## 详细步骤

### 步骤 1: 准备测试环境

#### 1.1 检查版本号

确保 `pubspec.yaml` 中的版本号已更新：

```yaml
version: 1.0.6+6  # 格式：版本号+构建号
```

#### 1.2 检查 .env 配置

确保 `.env` 文件配置正确（指向生产环境）：

```bash
# 验证配置
cat .env

# 应该包含：
# SUPABASE_URL=https://your-project.supabase.co
# SUPABASE_ANON_KEY=your-production-key
```

#### 1.3 启动测试设备

选项 A - 使用模拟器：
```bash
flutter emulators --launch <emulator_id>
```

选项 B - 连接真机：
```bash
adb devices
# 验证设备已连接
```

### 步骤 2: 运行自动化冒烟测试

```bash
cd /path/to/exhibition-buyer-app
chmod +x scripts/smoke_test.sh
./scripts/smoke_test.sh
```

**预期结果**：
```
✅ 冒烟测试全部通过！Release APK 可以发布
```

**如果测试失败**：
1. 查看失败的测试项
2. 检查错误日志
3. 修复问题
4. 重新运行测试

### 步骤 3: 快速手动测试

在真机上执行以下测试：

#### 3.1 安装测试
```bash
# 安装 APK 到真机
adb install build/app/outputs/flutter-apk/app-release.apk
```

验证：
- [ ] 安装成功
- [ ] 应用图标显示正常

#### 3.2 启动测试

1. 点击应用图标
2. 计时：从点击到显示登录页面应该 < 5 秒
3. 验证：
   - [ ] 无崩溃
   - [ ] 无黑屏或白屏
   - [ ] 启动画面显示正常

#### 3.3 登录测试

1. 输入测试账号：`test@example.com`
2. 输入密码：`test123456`
3. 点击登录
4. 验证：
   - [ ] 登录成功或显示清晰错误提示
   - [ ] 进入场次选择页面

#### 3.4 核心功能测试

1. 创建或进入场次
2. 创建或进入摊位
3. 进入照片列表
4. 验证：
   - [ ] 页面跳转流畅
   - [ ] 列表可以滚动
   - [ ] 按钮点击有反馈

### 步骤 4: Git Tag 和推送

确认测试通过后，创建版本标签：

```bash
# 创建 Git Tag
git tag -a v1.0.6 -m "Release version 1.0.6"

# 推送 Tag 到远程
git push origin v1.0.6
```

### 步骤 5: CI 自动化测试和发布

推送 Tag 后，GitHub Actions 会自动：

1. 运行冒烟测试
2. 构建 Release APK
3. 创建 GitHub Release
4. 上传 APK 到 Release

监控 CI 状态：
```
https://github.com/<your-repo>/actions
```

### 步骤 6: 发布后验证

#### 6.1 验证 Release 创建成功

访问 GitHub Releases 页面：
```
https://github.com/<your-repo>/releases
```

验证：
- [ ] Release 已创建
- [ ] APK 文件已上传
- [ ] Release 描述显示"冒烟测试已通过"
- [ ] 版本号正确

#### 6.2 下载并测试发布的 APK

1. 从 GitHub Release 下载 APK
2. 在真机上安装
3. 快速测试启动和登录
4. 验证：
   - [ ] 下载链接可用
   - [ ] APK 能安装
   - [ ] 应用能正常使用

#### 6.3 通知团队

发送发布通知：

**邮件/Slack 模板**：
```

- 优化照片加载性能

```

## 测试标准

### 阻塞性问题（必须修复）

以下问题会阻止发布：

1. **应用无法启动**
   - 启动崩溃
   - 启动卡住超过 10 秒
   - 显示黑屏或白屏

2. **核心功能失效**
   - 无法登录
   - 无法创建场次
   - 无法拍照上传

3. **严重性能问题**
   - 启动时间 > 10 秒
   - 页面切换卡顿 > 3 秒
   - 应用频繁崩溃

4. **数据安全问题**
   - 密码明文显示
   - 未授权访问数据
   - HTTPS 降级到 HTTP

### 非阻塞性问题（可后续修复）

以下问题可以发布后修复：

1. **UI 美观问题**
   - 颜色不一致
   - 间距不完美
   - 动画不流畅

2. **次要功能问题**
   - 某个不常用功能失效
   - 错误提示不够友好
   - 某些设备上显示异常

3. **性能优化**
   - 照片加载可以更快
   - 内存占用可以更低
   - 网络请求可以更优化

## 回滚流程

如果发布后发现严重问题：

### 1. 立即停止分发

在 GitHub Release 页面：
1. 编辑 Release
2. 勾选 "Set as a pre-release"
3. 在描述中添加警告：⚠️ 此版本存在严重问题，请勿使用

### 2. 通知用户

发送紧急通知：
```
⚠️ 紧急通知

v1.0.6 版本存在严重问题，请暂时不要更新。

已知问题：<描述问题>
影响范围：<描述影响>

我们正在修复，预计 2 小时内发布修复版本。

如已安装 v1.0.6，请卸载并重新安装 v1.0.5：
https://github.com/<your-repo>/releases/tag/v1.0.5
```

### 3. 快速修复并发布

1. 修复问题
2. 更新版本号（如 v1.0.7）
3. 重新执行冒烟测试流程
4. 快速发布新版本
5. 通知用户问题已解决

## 常见问题

### Q1: 冒烟测试和完整测试的区别？

**冒烟测试**：
- 目标：快速验证基本功能
- 时间：5-15 分钟
- 覆盖：启动、登录、核心流程入口
- 频率：每次构建 Release APK

**完整测试**：
- 目标：全面验证所有功能
- 时间：1-2 小时
- 覆盖：所有功能、边界情况、异常处理
- 频率：重大版本发布前

### Q2: 自动化测试失败，但手动测试通过怎么办？

可能原因：
1. 模拟器环境问题
2. 测试脚本需要更新
3. 网络环境不同

建议：
1. 在真机上再次验证
2. 记录问题并更新测试脚本
3. 如果真机测试通过，可以发布

### Q3: CI 测试超时怎么办？

解决方法：
1. 增加超时时间（`.github/workflows/pre_release.yml`）
2. 优化测试脚本
3. 使用更快的 CI runner

### Q4: 如何在本地模拟 CI 环境？

使用 `act` 工具：
```bash
# 安装 act
brew install act  # macOS

# 运行工作流
act push -j smoke-test
```
